## 0. 背景与边界

| 项 | 口径 |
|----|------|
| 现网痛点 | UGC-2b 用 **jsfeat 投影切规则 4/9 宫格**，须手选四宫/九宫；不规则摆放/6 宫/散落桌面效果差 |
| 升级目标 | **服务端视觉大模型（VLM/视觉检测）** 对整页图返回多卡 **bbox（归一化坐标）** → 服务端切图 → **现有确认页** → 仍走 UGC-1 |
| 与原 2b | 确认后业务（模式 A 批量申请 / B 匹配入柜）、禁止未确认灌库、禁止「仅私人」——**不变** |
| 与方向稿 | 原 F-R2「非大模型」针对规则宫格时代；本升级 **明确放开检测环节用视觉模型**；**自动写特典文案灌库仍 Out** |
| 端 | **微信小程序优先**；H5 宫格仍 Out |

---

## 1. 一句话

用户上传整页小卡照片（规则或不规则）；**服务端**调视觉模型检出每张卡的位置与张数并切割；用户在确认页调框/删卡后，按卡走 **UGC-1 先审后发申请** 或 **匹配已有 published 挂拥有**——**禁止**未确认、未审核直接 published。

---

## 2. In Scope

### 2.1 检测与切图（本切核心）

| # | 能力 | 口径 |
|---|------|------|
| 1 | 整页上传 | 相册/拍照；**不再强制**先选手选 4/9（可保留「提示：尽量平铺、少遮挡」） |
| 2 | 服务端 VLM 检测 | API：整页图（或压缩件）→ 模型返回 `cards[{ bbox: [x1,y1,x2,y2] 归一化 0–1, confidence? }]` 及建议张数 |
| 3 | 服务端切图 | 按 bbox 裁切 → 生成多张候选卡面（可再压 ≤ 现网投稿上限） |
| 4 | 确认页 | **复用/延续** 2b 确认 UI：调框、删卡、旋转、补单卡；**必须人工确认**后才提交 |
| 5 | 入库 | 确认后：**A** 每卡 `pending_review` submission；和/或 **B** 近 dup 命中 published → 挂拥有；白名单/协议/机审同 UGC-1 |
| 6 | 模型「建议」字段 | 允许返回成员名/特典名等 **建议**；UI 预填但 **须用户确认**；**不得**静默写入 published 文案 |

### 2.2 与旧 CV（jsfeat）

| 方案 | 说明 | **建议默认** |
|------|------|----------------|
| **A. VLM 主路径 + CV 降级** | VLM 失败/超时 → 可选试规则 4/9 或直接降级单卡 UGC-1 | **采纳** |
| **B. 仅 VLM** | 删除手选四宫/九宫与 jsfeat | 若降级成本低可二期删 |
| **C. CV 仍为主、VLM 旁路** | 与用户拍板冲突 | **否决** |

手选「四宫/九宫」：**主路径移除强制选择**；降级 UI 可保留「手动规则宫格」入口（OQ）。

### 2.3 工程约束

| # | 口径 |
|---|------|
| 调用位置 | **仅服务端**（密钥不出端；可审计、限流） |
| 禁止 | 小程序/H5 端侧跑大模型权重 |
| 超时 | 明确超时（建议默认 **15–20s**）→ 降级文案 |
| 计费 | 每页 1 次检测（重试有上限）；见 OQ 日/月封顶 |
| 整页图 | 检测用毕：确认提交后按 pending 生命周期；用户取消宜尽快删 |

## 6. 风险

| 风险 | 等级 | 缓解 |
|------|------|------|
| 费用飙升 | 高 | 日限额、压缩后再送、禁止无意义重试刷量 |

| 与旧 CV 双栈维护 | 中 | VLM 主路径；CV 仅降级；文档写清 |
| 审核队列暴增 | 中 | 每页提交上限；白名单团 |
