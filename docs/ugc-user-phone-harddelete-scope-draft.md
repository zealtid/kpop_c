## 0. 背景与边界

| 项 | 口径 |
|----|------|
| 现网 | 微信 `code` 登录；用户资料以 openId/unionId 为主；Admin 用户管理偏只读（P3-U）；**无**默认硬删 |
| 本切目标 | C 端可授权绑定手机号；Admin 可见/筛手机号并记绑定事件；Admin **硬删**用户 + 审计 |
| 登录 | **仍走微信**；手机号是资料/联系维度，**不是**独立登录凭证 |
| Out 总则 | 不做短信验证码独立登录；不改 Admin ops 登录方式（除非实现硬删时必须捎带说明现网 allowlist） |

---

## 1. 一句话

微信小程序用户可通过 **getPhoneNumber** 授权绑定手机号（登录仍微信）；后台可查看、筛选绑定号并记录绑定审计；运营在 Admin 对指定用户执行 **硬删除**（清关联数据）并强制写审计与二次确认。

---

## 2. In Scope

### 2.1 手机号绑定（小程序）

| # | 能力 | 口径 |
|---|------|------|
| 1 | 授权入口 | 「我的」或设置页：按钮触发微信 **getPhoneNumber**（需符合微信开放能力与类目要求） |
| 2 | 服务端换号 | 前端把 `code`（phone code）交服务端；服务端调微信接口解析手机号；**禁止**前端直出完整号写入本地当作唯一真相 |
| 3 | 落库 | `users`（或等价表）存 `phone_e164` / `phone_masked` 等；唯一性策略见 OQ-P1 |
| 4 | 登录不变 | 会话仍由微信登录签发；未绑定手机号**不挡**登录与基础使用（除非产品另定强制绑定——本切默认**不强制**） |
| 5 | 解绑/换绑 | 本切建议支持「重新授权覆盖」；是否允许清空见 OQ-P2 |

### 2.2 Admin：看见 / 筛选 / 绑定事件

| # | 能力 | 口径 |
|---|------|------|
| 1 | 列表字段 | 用户列表展示 **脱敏手机号**（如 `138****5678`） |
| 2 | 筛选 | 支持按手机号精确或后四位/完整号查询（权限内；防遍历见 OQ-P3） |
| 3 | 详情 | 用户详情可见脱敏号；完整号仅高权限或点击「显示」+ 记审计（建议默认脱敏，OQ-P4） |
| 4 | 绑定事件日志 | 专用表或审计流：`user_id`、`actor`（user self / system）、`event`（bind_success / bind_fail / rebind）、`at`、失败原因码、**展示用脱敏号**；**不**把明文永久堆在前端日志 |
| 5 | 与 P3-U | 在现有后台用户管理上扩展，不另起无关 CRM |

### 2.3 Admin：硬删用户

| # | 能力 | 口径 |
|---|------|------|
| 1 | 硬删定义 | **物理删除**（或等价不可恢复清理），**不要默认软删**（`deleted_at` 留行不算完成本切） |
| 2 | 二次确认 UI | 输入确认词（如用户昵称/Id）或勾选风险声明 → 再调删除 API；误点不可一键删 |
| 3 | 权限 | 仅 ops allowlist 中授权角色；建议比「只读用户」更高权限位 |
| 4 | 审计（强制） | 删除前写审计：`actor_admin_id`、`at`、`target_user_id` / openId 摘要、**关联清理摘要**（删了哪些表/行数）、请求 IP/UA 可选 |
| 5 | 清理范围（须实现或明确级联） | 见 §2.4 |

### 2.4 硬删范围（数据）

| 数据域 | 口径 |
|--------|------|
| 用户主行 | `users`（及 profile 扩展行）删除 |
| 身份/会话 | 微信 openId/unionId 映射、refresh/access **token/会话**、设备登录态失效 |
| 拥有与愿望 | UserCard / 拥有关系、UserWant 等柜数据 |
| UGC | 该用户 `catalog_submissions` / 私人卡申请等投稿行；对象存储 **orphan 策略**见 OQ-D1（元数据删；文件可异步 GC） |
| 积分流水 | 用户积分余额与流水删除或按审计快照后删（须在清理摘要中写明） |
| 绑定审计 | **保留**手机绑定事件中与「已删用户」相关的脱敏审计，或快照进删用户审计后删明细——建议 **删用户审计永久保留**，绑定明细可匿名化 |
| Feed/社交 | 若有该用户动态/评论：删或匿名化（现网有则写进清单；无则 N/A） |
| Admin 操作者 | **不**删 ops 账号本身 |

---

## 3. Out of Scope

| Out | 说明 |
|-----|------|
| 短信验证码独立登录 | 手机号不是登录因子 |
| 改 Admin ops 登录 | 仍现网 allowlist/现方式；本切不升级 SSO |
| 默认软删 | 本切交付物是硬删 |
| 批量删用户 / 按筛选一键清空 | 本切单用户硬删 |
| 用户自助注销全流程合规包 | 可后置；若做须另开（隐私协议、冷静期） |
| 向第三方同步手机号营销 | 禁止无同意外传 |

---

## 4. 与现网差异摘要

| 维度 | 现网 | 本切 |
|------|------|------|
| 手机号 | 通常无绑定 | getPhoneNumber 绑定 + Admin 可见/筛 + 绑定事件 |
| 登录 | 微信 | **仍微信** |
| 删用户 | P3 偏禁批量删 / 无硬删产品化 | **单用户硬删 + 二次确认 + 审计** |

---

## 5. 验收条目（建议）

**手机号**  
1. 小程序可拉起 getPhoneNumber；成功后资料页显示脱敏号。  
2. 服务端存号；Admin 列表可筛；绑定成功/失败有事件记录（含时间、结果）。  
3. 未绑定用户仍可微信登录使用（若未拍「强制绑定」）。  

**硬删**  
4. Admin 对测试用户执行硬删后：登录态失效；users 行不存在；拥有/投稿等约定表无残留主数据。  
5. 审计表存在一条含 actor、时间、target、清理摘要的记录；二次确认缺失时 API 拒绝。  
6. 无「仅 deleted_at」冒充完成。

## 6. 开放问题

| ID | 问题 | 建议默认 |
|----|------|----------|
| OQ-P1 | 同一手机号绑定多微信 | **禁止**（unique）；冲突提示「已被其他账号绑定」 |
| OQ-P2 | 是否允许解绑清空 | 本切 **仅允许换绑**；清空后置 |
| OQ-P3 | 列表防遍历 | 完整号查询限频 + 仅精确匹配 |
| OQ-P4 | Admin 是否默认可看完整号 | **默认脱敏**；「显示完整」写审计 |
| OQ-D1 | COS/OSS 上用户图是否同步物理删 | 元数据先删；文件 **异步 GC**（24h 内）并写入清理摘要「queued_gc」 |
| OQ-D2 | 已 published 且源自该用户投稿的图鉴行 | **保留图鉴**（平台资产）；仅断开放归用户关联；摘要注明 `catalog_kept` |
| OQ-D3 | 硬删与合规（个人信息删除权） | 本切先满足运营硬删；正式「用户注销」另开并补协议文案 |

## 7. 风险与影响声明

| 风险 | 缓解 |
|------|------|
| 误硬删不可恢复 | 二次确认 UI；仅高权限；审计可追溯「谁删的」但数据不回滚 |
| 级联不干净致脏数据/唯一约束占位 | 删除服务单测 + 清单化表；开闸前 DBA/后端核对 FK |
| 手机号泄露 | 脱敏展示、传输 HTTPS、日志禁明文、Admin 显号审计 |
| 微信能力类目/资质 | 上线前确认小程序类目支持手机号快速验证组件 |
| 影响声明 | **不改** UGC-1 审核状态机；**不改** 宫格 VLM 主路径；**不引入**短信登录 |
