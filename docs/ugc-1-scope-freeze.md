## 0. Q1–Q6 拍板（本切片锁定）

| # | 结论 | 写入本冻结 |
|---|------|------------|
| **Q1** | 卡背 **一律选填** | 校验：卡面必填；卡背可选 |
| **Q2** | **先审后发** | 待审稿不进公开图鉴、不进完成度分母；通过后才 `published`/合并可见 |
| **Q3** | **主图审过才可换** | 合并已有模板时：仅审核通过动作可替换权威主图；用户投稿不得直接覆盖 |

| **Q6** | 私人加卡页内合并「申请入库」，与投稿 **共用同一流程 UI** | 入口可多、流程一；见 §2.2 |

## 1. 一句话

在白名单团体内，用户经短路径提交单卡（卡面必填、卡背选填）进入待审；运营在 Admin 审核通过后创建或合并公开模板（去重一份、主图仅审过可换）；驳回/违规图及时删除不留档。私人加卡仍可私人保存，并可用同一套 UI 申请入库。

## 2. In Scope（UGC-1）

对齐方向稿 §4 **P0 + P1**（下列 ID 便于对照 Notion）；实现细节以日后可研发包为准。

### 2.1 数据 / 存储 / 底座（P0 + 压缩正反面 P1）

| ID | In | 口径 |
|----|-----|------|
| F-D1 | 公开模板去重（指纹 + 业务键，一份主资源） | 通过时创建或合并；禁止重复 published 膨胀 |
| F-D2 | 投稿/申请实体与 Template 分离 | 状态至少：`draft_local`（仅私人）/ `pending_review` / `approved`（已合并）/ `rejected` |
| F-D3 | 驳回与违规 **删对象存储图**；元数据可审计 | SLA：驳回后尽快清图（建议小时内；实现订 SLA） |
| F-D4 | 统一压缩（压缩件 + 缩略图） | 上传链路必经 |
| F-D5 | 卡面 / 卡背字段；图鉴侧可翻转展示 | 卡背选填（Q1）；有背则可翻 |
| F-D7 | 官方养团/成员（+ 必要发行壳）；UGC 不改底座写权限 | 用户不可改 Group/Member 主数据 |
| F-D8 | 公私分桶 | 私人图 ≠ 公共模板对象；待审稿独立前缀/桶策略 |

### 2.2 C 端流程（P1 · 按 Q6 修正入口）

| ID | In | 口径 |
|----|-----|------|
| F-C1′ | **入口**：① 投稿入口；② **私人加卡页内「申请入库」** | 二者共用 **同一流程 UI**（字段、压缩、提交、进度态） |
| F-C2 | 短路径 | 团（∈白名单）→ 专/版本·特典 → 卡面（必）→ 卡背（选）→ 协议勾选 → 提交 |
| F-C3 | 版本·特典选择 | 对接现网 Release.versions；有刀 A 数据时可提示，无则手选/手填策略与现网一致 |
| F-C4 | 投稿人站内进度 | 待审 / 通过 / 驳回（含原因若有）；**无订阅消息**（Q5） |
| F-C5 | 通过后挂卡 | 用户「拥有」可指向合并后的官方 Template；完成度按 M1 官方口径 |

**私人加卡（M1.5）并存：**

- 仅保存私人：行为不变（私人柜、不进 published）  
- 点「申请入库」：进入与投稿相同的待审流（须补齐专辑/版本·特典等公开字段；卡背仍选填）  
- 私人自拍/图在 **驳回入库** 或 **内容安全拒绝** 后：按口径清公共/待审对象；私人副本是否保留见 §6 OQ（默认建议：入库申请驳回可保留私人卡，**申请用的待审副本图删除**；纯私人机器驳回仍清私人违规图——对齐 M1.5 + 方向口径 2）

### 2.3 识别预处理（P1 轻量；非大模型）

| ID | In | 口径 |
|----|-----|------|
| F-R1 | 单卡边缘/透视矫正（可选增强） | 成熟 CV；失败则原图提交 |
| F-R3 | 近 dup 提示 | 提交前提示「可能已有模板」；不阻断提交（审核侧再判） |
| F-R4 | 清晰度/过暗过曝预检 | warning 可继续；极端可挡 |

**不做（留给 UGC-2）：** F-R2 宫格 4/9、F-C7/C8 整页批量。

### 2.4 审核运营（P1）

| ID | In | 口径 |
|----|-----|------|
| F-A1 | 审核队列 | 待审优先；按团/专筛；挂现 Admin Vue；窄屏可用 |
| F-A2 | 详情对照 | 投稿图 vs 疑似已有模板（指纹候选） |
| F-A3 | 一键通过 / 驳回 | 通过：创建 Template 或合并；驳回：写原因 + **删待审图** |
| F-A4 | 审中改业务字段 | 版本·特典·成员等改完再入库 |
| F-A8 / F-S3 | 举报 / 强制下架 | 已 published 可下架；下架策略与清图/保留审计另遵合规 |
| — | **白名单维护（Q4）** | Admin：团体 UGC 开放开关/列表；非白名单 C 端不可提交入库 |

**主图替换（Q3）：** 仅审核「通过并设为权威主图」可换；普通合并默认保留原主图除非审核员显式勾选「采用本稿主图」。

## 4. 状态机（摘要）

```
[私人仅保存] --申请入库--> pending_review --通过--> Template published/合并
                              |                      ^
                              +--驳回--> 清待审图 ----+（可留私人卡，见 §2.2）
上传/机器违规 ------------------> rejected + 清相关图
```

- `pending_review`：**先审后发**；C 端他人不可见；不算官方完成度  
- 通过后：去重合并；主图按 Q3
